## 看它解决的问题

先读 README 中的功能说明与示例，找到自己的具体任务。一个功能丰富的项目，不一定适合一个简单需求。

## 看维护与使用门槛

- 最近的发布与提交是否仍在持续？
- 文档是否说明系统、显卡、模型 API 等依赖？
- Issue 中是否有与你相同的环境问题？
- 开源许可证是否允许你的使用方式？

Star 数可以反映关注度，但不能替代这些检查。

## 用一个小任务验证

给项目一个清晰、有限的任务，例如“从一份 PDF 提取带来源的摘要”。记录输入、输出、耗时和失败条件，再决定是否接入日常工作流。

## 为下次复用留一张卡片

```markdown
## 项目名称
- 仓库链接：
- 解决的问题：
- 安装与运行要求：
- 最小使用示例：
- 已验证的效果：
- 已知限制：
- 检查日期：
```

先完成一次小规模验证，再考虑复杂集成，可以减少许多无效配置。
